# 线程累计与本地归档口径

紧凑条和详情面板显示的总额不是同一个统计对象。两者不一致通常不是漏数，而是作用域不同。

## 紧凑条“会话”

来源：

```text
最后一次 thread_token_usage.total
```

经过 reset-aware normalizer：

- 累计上升时直接接续；
- 权威 `total` 跌到上一值的一半或更低时，视为完整重置；
- 更小的回落是主机尾部修订，不重复加入旧累计。

这个值表示**完整线程累计**。如果宿主日志的首条可观测记录之前已经有历史，这部分基线也会
包含在计数器中，但它没有足够的时间信息用于本地日范围归类。

## 详情“统计信息”

来源：

```text
<historyDir>\sessions\<sessionHash>\turns.json
```

页面按 `today / 3d / 7d / 30d / all` 汇总所有会话中仍可定位到轮次的数据，最多保留 60 天。

它表示**本地可定位归档量**：

- 不包含首条日志之前无法归类的线程基线；
- 不读取消息正文；
- 旧快照缺少计时字段时只影响耗时，不影响 Token 数；
- 时间范围越小，越可能与紧凑条不同。

## 为什么“全部”仍可能小于紧凑值

“全部”表示本地归档中的全部可定位轮次，不等同于完整线程生命周期。即使选中“全部”，首条
可观测日志之前的线程基线仍没有日期，无法安全加入任何时间范围。

当前设备曾出现的实机示例：

```text
紧凑条完整线程累计：约 2.91B
详情“全部”可定位归档：约 1.84B
```

差额主要来自首条可观测日志之前的线程基线，以及其他无法按轮次重新归类的累计。

## 显示规则

- 详情“总量”悬浮提示会说明“本地归档不等于完整线程累计”。
- 紧凑条始终显示完整线程累计。
- 详情顶部时间范围只控制本地归档汇总，不改变紧凑条口径。
- 范围缓存只缓存此前的归档汇总，不改变数字定义。

## 何时两条路径可能接近

只有线程从第一条可观测记录开始累计，且全部轮次都在本地保留期内时，两个数字才可能接近
或一致。存在以下任一情况时不要求相等：

- 会话在首条保留日志前已经开始；
- rollout 文件发生迁移、截断或分片；
- 线程累计包含无法定位日期的历史基线；
- 历史数据超过 60 天保留期。

因此禁止把“紧凑条总额 = 详情全部归档”作为回归测试条件；正确条件是各自遵循本文口径，
并通过固定 fixture 分别验证。
